security fix Account-isolation bug — a new signup could inherit an old account
ANDROID_ID survives a reinstall; a brand-new account on a device that previously held a different one silently merged into that old account's entire row instead of creating its own.

userResolver.ts's getOrCreateUserInternal fell back to a deviceId-only lookup whenever a new firebaseUid didn't match an existing row — and since that deviceId already belonged to someone, the "new" signup just became them. Now a firebaseUid with no match always creates a genuinely new row; the device's claim moves to it, and the old account releases that claim but keeps every field of its own data (deviceId is now nullable for exactly this reason).

Only prevents this going forward. If an account got merged before this deployed, that merge already happened in the database and needs a direct fix — say so if you hit it.

phase 1 shipped, 3 to go Live AR Face Swap — real-time Snapchat-style warp, recording, voice changer
A 4-phase build. Phase 1 (live camera + sticker filters) shipped this pass — see above. Phases 2–4 (actual live face-swap warping, baking it into recorded video, and wiring up a dead-but-fully-built voice-changer module) are planned but not started.

Phase 2 — the hard part: real-time warp of a chosen target face onto the live tracked face. Needs MediaPipe Tasks Vision's FaceLandmarker (478-point mesh — ML Kit's ~133-point contour isn't dense enough) plus a from-scratch OpenGL compositor, neither of which exist anywhere in this app today. This is a genuinely hard multi-week CV/graphics problem even for experienced teams, not a quick add — expect visible seams in a first pass.

Phase 3: bake the composited output into a real saved video file (default plan: record raw, then re-apply the effect on export via media3-transformer, already a dependency — trades true WYSIWYG recording for a guaranteed-correct save).

Phase 4: wire util/VoiceFxProcessor.kt — fully built (ROBOT/CHILD/ALIEN/MAN/WOMAN/MONSTER/TACTICAL presets, real PCM pitch-shift/ring-mod/distortion) but with zero callers anywhere — into real voice-message recording first (low risk), then optionally live AI playback and live user-to-user calls (the latter needs a spike: WebRTC's native audio capture has no confirmed app-level hook to intercept/mutate samples).

No physical device or emulator in this environment at any point so far. Every phase above compiles clean but frame rate, tracking accuracy, mirroring correctness, and warp visual quality all need validation on real hardware before they can be called done — not just built. Full phase-by-phase file list in ~/.claude/plans/elegant-knitting-nygaard.md.
